## 1. ESM 化：先拍板 4 件事（**没定完不要动手**）

| # | 决策 | 选项 | 我的建议 |
|---|---|---|---|
| D1 | 发布形态与 `engines` | ① 只发 ESM 源码 + `index.cjs` 转发，`engines` 提到 `>=22.12` ② 双产物构建（`exports.import`→ESM、`exports.require`→编译出的 CJS），`engines` 保持 `>=20` | **②**。框架要给别人用，不能在 Node 20 上 `require` 失败；双产物是这个体量包的标准做法 |
| D2 | 测试与 fixtures 的模块体系 | ① 转 ESM `.mts`/`.mjs` ② 保持 CJS，走 `require(ESM)` | **①**。一致性优先（D1 选了双产物后，测试转 ESM 不再有兼容顾虑）|
| D3 | worker 加载用户 Actor 模块 | ① 继续 `createRequire`（支持 CJS 与 ESM 两种用户模块）② 只支持 ESM | **①**。用户模块形态不该被框架强制 |
| D4 | 构建产物位置与是否入库 | ① `dist/` 不入库，发布前 `npm run build` ② 入库 | **①**，并在 `prepublishOnly` 里强制构建 |

**为什么必须先定**：`"type": "module"` 是**包级**开关，会同时作用于 `src/**`、`test/**`、`test/fixtures/**`；
不定 D1/D2 就动手，只能得到"一半 ESM 一半 CJS"的混合包——这正是本次会话走过的弯路（见 §4）。

## 2. ESM 化执行方案（一次性，不分批）

1. **定完 §1 的四项决策**，把结论写进 `docs/design/m0/01` 的对应章节；
2. **一次性转换全部文件**：`python3 tools/codemods/ts-to-mts-incremental.py <全部 src/**/*.ts>`
   （转换器已固化四条经 AST 断言验证的规则：`__dirname`/`__filename`、硬编码文件名字符串、
   `Object.assign` 属性挂载、解构重命名 `导出名 as 本地名`）；
3. **产物级对账**（必须为 0 异常）：逐条校验产物里的说明符——`node:` 前缀必须是真内置
   （注意 `node:test` 不在 `module.builtinModules` 里）、相对说明符必须能解析到真实文件；
4. **同步转换** `packages/core/test/**` 与 `test/fixtures/**`（保持同一模块体系）；
5. **替换入口**：`index.mjs` 由源码直接承担；CJS 侧按 D1 提供 `index.cjs` 或 `dist/cjs`；
6. **验收清单**：281/281 通过 · 严格 typecheck 0 错误 · 打包后在临时工程里
   `require()` 与 `import` 两条路径都可用 · 示例全部可跑。

> 纪律（本次会话用血换来的）：**先提交工具 → 再跑批次 → 失败只回退代码**；
> 提交前断言指标（测试数 + 类型错误数），断言失败**不提交**；断言要落在代码结构（AST）上，
> 不要用"字符串存在"（注释里也会出现，会造成假通过）。

## 3. 其他待办（按价值排序，与 ESM 化互相独立）

| 优先级 | 事项 | 说明 / 现状 |
|---|---|---|
| 高 | **类型债收口** | 实测编辑器视角（全量 src + strict）曾有 **1806** 个错误（1126 个"属性不存在"多来自 JS 时代的 `options.xxx` 取值 + 502 个隐式 any）。现已改为**标准迁移做法**：43 个未类型化文件带 `// @ts-nocheck` 显式标记（不是隐藏错误，而是"暂未类型化"的声明），4 个已类型化文件（`config.ts`、`obs/alerting.ts`、`ops/token.ts`、`ops/ws-server.ts`）进入严格检查。**收口方式**：删掉一个文件的 `@ts-nocheck` → 修该文件的错误 → 它自动进入门。`test/types/**` 暂移出程序（它测 `.d.ts` 声明面，而源码同名 `.ts` 实现现在优先被解析），待实现补齐类型后再收回 |
| 高 | **M0.2 内核原语** | 定时器（可注入时钟，先做虚拟时钟）、FSM、stash、receive-timeout、消息校验——签名与测试计划见 `docs/design/m0/02-primitives.md` |
| 中 | **插件拆包（M1）** | `plugins/**` 目前在 core 内，导致 `require('nodejs-actor-framework')` 加载 32 个模块；目标 ≤15。拆成 `@actor/plugin-*` 后按需加载 |
| 中 | **配置 / DI / 插件 SDK（M1）** | 见 `docs/design/01`；目标是业务侧零框架耦合的装配方式 |

## 4. 本次会话的失败记录（写下来，避免重犯）

| 弯路 | 代价 | 结论 |
|---|---|---|
| 整体翻转 `"type": "module"`（忽略它作用于 src+test+fixtures） | 三次失败，27 个用例加载失败 | 包级开关必须**一次性**处理；先定发布形态 |
| 转换器补丁与代码改动同处一份未提交工作树，失败后 `reset --hard` | 三次丢失工具改进，反复在旧文件上打补丁 | **先提交工具，再跑批次** |
| 断言写成"字符串存在"（注释里也有同样的字） | 多次假通过，把"未生效"当"已生效" | 断言落在 **AST** 上；提交前断言指标 |
| 解构重命名方向写反（`\2 as \1`），靠推理连补两轮 | 两轮白费 | **先 grep 产物，再改代码** |
| 无条件 `print('已写入')` / 提交信息里写未验证的结论 | 文档与代码不一致、错误记录入历史 | 打印放在断言之后；断言失败非零退出 |

## 5. 明确不做（Non-goals）

- 不在内核里做 HTTP 路由、控制器、ORM（分层：L1 内核 ← L2 运行时服务 ← L3 可选的 `@actor/web|data|testkit|cli`，依赖方向严格向下）；
- 不支持装饰器（实测 Node 的类型剥离不支持装饰器，主线不引入）；
- 不做"每个请求一个 Actor"这类反模式（反模式列表见 `docs/design/00`）；
- 不为了"更现代"牺牲一致性（`.ts`/`.mts` 混用已否决）。
