# 数据库（@actor/db）

`@actor/db` 是**应用层**的数据库能力：方言（PostgreSQL 默认 / MySQL / SQLite）、连接与连接池管理、
model 声明、以及实体 ↔ 行的 ORM 映射。设计见 [M6 设计](../../design/m6-db-package.md)。

## 先装驱动（框架不引任何运行时依赖）

框架**不带**数据库驱动，按你要用的方言在自己项目里装：

| 方言 | 装什么 | 说明 |
|---|---|---|
| `sqlite`（默认可用） | **不用装** | Node 24 内置 `node:sqlite`，零依赖 |
| `pgsql`（默认方言） | `npm i pg` | 懒加载；没装时启动会明确告诉你装什么 |
| `mysql` | `npm i mysql2` | 同上 |
| `mssql` | `npm i mssql` | SQL Server（T-SQL）；同样懒加载 |

驱动是从**你自己项目的 node_modules** 解析的（不是从框架包里），所以 pnpm/yarn 的严格布局也没问题。

## 连接配置：DSN 或字段式

```js verify
import { createDatabase, describeConnection } from '@actor/db';

// 1) DSN（推荐放环境变量）
const fromUrl = createDatabase({ connection: { url: 'pgsql://app:secret@db.internal:5432/appdb' } });
console.log('url  →', fromUrl.dialect, describeConnection(fromUrl.connection));

// 2) 字段式
const fromFields = createDatabase({
  dialect: 'mysql',
  connection: { host: 'db.internal', user: 'app', password: 'secret', database: 'appdb' },
  pool: { max: 20, idleTimeoutMs: 30_000, connectionTimeoutMs: 5_000 },
});
console.log('fields →', fromFields.dialect, describeConnection(fromFields.connection));

// 密码**不会**出现在 describeConnection / 错误信息里（有测试盯着）
if (describeConnection(fromFields.connection).includes('secret')) throw new Error('密码泄漏了');

// 3) 不写 dialect 时默认 pgsql；sqlite 用 filename（:memory: 是内存库）
const lite = createDatabase({ dialect: 'sqlite', connection: { filename: ':memory:' } });
console.log('sqlite →', describeConnection(lite.connection));
```

连接的建立、探活、优雅关闭都由框架负责：

```js verify
import { createDatabase } from '@actor/db';

const db = createDatabase({ dialect: 'sqlite', connection: { filename: ':memory:' } });
await db.connect();                        // 建池 + 一次 SELECT 1（失败即抛，不静默降级）
console.log('health →', JSON.stringify(await db.healthCheck()));
console.log('stats  →', JSON.stringify(db.stats()));

await db.close();                          // 幂等；关闭后 healthCheck() 会如实返回 ok:false
console.log('after close →', (await db.healthCheck()).ok);
if ((await db.healthCheck()).ok) throw new Error('关闭后不该还报健康');
```

## model 层：你写声明，框架生成表

```js verify
import { defineModel } from '@actor/db';

const Note = defineModel({
  name: 'notes',
  fields: {
    id: { type: 'uuid', primaryKey: true },              // uuid 主键由仓储自动生成
    title: { type: 'string', length: 200, notNull: true },
    tags: { type: 'json', default: [] },                 // JSON 列（三方言统一编解码）
    ownerId: { type: 'string', column: 'owner_id' },     // 列名映射
    archived: { type: 'boolean', default: false },
    createdAt: { type: 'timestamp', auto: 'create' },    // 插入时自动写
    updatedAt: { type: 'timestamp', auto: 'update' },    // 每次更新自动写
    version: { type: 'integer', version: true },         // 乐观锁
  },
  indexes: [{ fields: ['ownerId'] }],
});

// DDL 是纯函数：不连库也能看清框架会发什么 SQL（这里看 PostgreSQL 与 MySQL 的差别）
console.log(Note.createTableSql('pgsql'));
console.log(Note.createTableSql('mysql'));
```

支持的逻辑类型（每个都会映射成方言正确的列类型）：

| 逻辑类型 | PostgreSQL | MySQL | SQLite | SQL Server | 说明 |
|---|---|---|---|---|---|
| `uuid` | `uuid` | `char(36)` | `text` | `uniqueidentifier` | 主键由仓储自动生成 |
| `string` | `varchar(n)` / `text` | `varchar(n)` / `varchar(255)` | `text` | `nvarchar(n)` / `nvarchar(max)` | 用 `length` 指定长度 |
| `char` | `char(n)` | `char(n)` | `text` | `nchar(n)` | 定长字符串，`length` 默认 1 |
| `text` | `text` | `text` | `text` | `nvarchar(max)` | 普通文本 |
| `tinyText` / `mediumText` / `bigText` | `text` | `tinytext` / `mediumtext` / `longtext` | `text` | `nvarchar(max)` | MySQL 的文本家族；PG/SQLite/T-SQL 只有一种大文本 |
| `tinyint` / `smallint` / `integer` / `bigint` | `smallint` / `smallint` / `integer` / `bigint` | `tinyint` / `smallint` / `int` / `bigint` | `integer` | `tinyint` / `smallint` / `int` / `bigint` | SQLite 只有整数 |
| `float` / `real` | `real` / `double precision` | `float` / `double` | `real` | `real` / `float` | 单精度 / 双精度（**注意 T-SQL 的命名正好相反**） |
| `decimal` | `numeric(p, s)` | `decimal(p, s)` | `numeric(p, s)` | `decimal(p, s)` | 定点小数，用 `precision`/`scale`（默认 10,2） |
| `boolean` | `boolean` | `tinyint(1)` | `integer` | `bit` | 领域里统一是 `boolean` |
| `date` / `time` | `date` / `time` | `date` / `time` | `text` | `date` / `time` | 领域里统一是 `'YYYY-MM-DD'` / `'HH:MM:SS'`（不带时区） |
| `timestamp` | `timestamptz` | `datetime(3)` | `text` | `datetimeoffset(3)` | **带时区**；领域里统一是 `Date`。⚠️ **T-SQL 的 `timestamp` 是 `rowversion`（版本号），不能用** |
| `dateTime` | `timestamp` | `datetime(3)` | `text` | `datetime2(3)` | **不带时区**；领域里也是 `Date` |
| `json` | `jsonb` | `json` | `text` | `nvarchar(max)` | 领域里统一是对象/数组（T-SQL 没有 json 类型） |
| `blob` / `binary` | `bytea` | `blob` / `varbinary(n)` | `blob` | `varbinary(max)` / `varbinary(n)` | 二进制 |

各方言还有几处**语句级**差异（不是类型能表达的，所以由方言描述符负责）：

| 差异 | PostgreSQL | MySQL | SQLite | SQL Server |
|---|---|---|---|---|
| 占位符 | `$1` | `?` | `?` | `@p1` |
| 标识符引号 | `"x"` | `` `x` `` | `"x"` | `[x]` |
| 自增整数主键 | `GENERATED BY DEFAULT AS IDENTITY` | `AUTO_INCREMENT` | `INTEGER PRIMARY KEY AUTOINCREMENT` | `IDENTITY(1,1)` |
| 回读生成的主键 | `RETURNING` | 结果里的 `insertId` | `RETURNING` | `SELECT SCOPE_IDENTITY()`（同批次） |
| 建表 | `CREATE TABLE IF NOT EXISTS` | 同左（+ 表级 `COMMENT=`） | 同左 | `IF OBJECT_ID(N'…') IS NULL EXEC(N'CREATE TABLE …')` |
| 加列 | `ALTER TABLE t ADD COLUMN c` | 同左 | 同左 | `ALTER TABLE t ADD c`（**不写 COLUMN**） |
| 索引 `IF NOT EXISTS` | 支持 | **不支持**（容忍"已存在"错误） | 支持 | **不支持** |
| 列注释 | `COMMENT ON COLUMN` | 建表时内联 | 不支持（如实报告） | `sp_addextendedproperty`（幂等写法） |

字段还可以带 **schema 注释**（给人看的，不是给你看的）。**注释不会自动更新**：
默认只在**建表时**写一次，已存在的表不会被 `sync()` 改动（改注释是显式决定，不是每次部署顺手改）：

| 策略（`migrations.comments` / 插件配置 `plugins.db.comments`） | 行为 |
|---|---|
| `never` | 从不写注释（连建表也不写） |
| `create`（默认） | 只在建表时写；已存在的表不动（`SyncReport.unsupportedComments` 会说明原因） |
| `always` | 每次 `sync()` 都重新应用（PG 的 `COMMENT ON` 是幂等的；MySQL 仍只在建表时能写） |


```js verify
import { defineModel } from '@actor/db';

const Note = defineModel({
  name: 'notes',
  comment: '用户笔记',                       // 表注释
  fields: {
    id: { type: 'uuid', primaryKey: true },
    title: { type: 'string', length: 200, comment: '标题（必填）' },  // 列注释
  },
});

// MySQL：注释内联在建表语句里
console.log(Note.createTableSql('mysql'));
// PostgreSQL：走独立的 COMMENT ON（sync 每次都会重新应用，幂等）
console.log(Note.commentSql('pgsql').join('\n'));
// SQLite：不支持列注释 → 如实返回空数组，sync 会在 unsupportedComments 里报告（不假装）
console.log('sqlite comments:', JSON.stringify(Note.commentSql('sqlite')));
```

## sync：建表、检测漂移、（可选）自动迁移

```js verify
import { createDatabase, defineModel } from '@actor/db';

const Note = defineModel({
  name: 'notes',
  fields: {
    id: { type: 'uuid', primaryKey: true },
    title: { type: 'string', notNull: true },
    ownerId: { type: 'string', column: 'owner_id' },
  },
});

const db = createDatabase({ dialect: 'sqlite', connection: { filename: ':memory:' } });
await db.connect();

console.log('首次 sync:', JSON.stringify(await db.sync([Note])));   // → created: ["notes"]
console.log('再次 sync:', JSON.stringify(await db.sync([Note])));   // → created: []（幂等）

// 手工造一个"少了 owner_id"的同名表 → 框架必须**明确报错**，而不是静默继续
await db.rawRun('DROP TABLE "notes"');
await db.rawRun('CREATE TABLE "notes" ("id" text NOT NULL PRIMARY KEY, "title" text NOT NULL)');
try {
  await db.sync([Note]);
  throw new Error('漂移没有被发现');
} catch (err) {
  console.log('漂移被拒:', err.name, '|', err.message.split('.').slice(0, 1).join(''));
}
await db.close();
```

想让它自动补**安全**的列，就在配置里显式打开（默认是关的）：

```js verify
import { createDatabase, defineModel } from '@actor/db';

const Note = defineModel({
  name: 'notes',
  fields: {
    id: { type: 'uuid', primaryKey: true },
    title: { type: 'string', notNull: true },
    ownerId: { type: 'string', column: 'owner_id' },
  },
});

// migrations.auto 只在**显式**配置时为 true：默认 sync() 只建不改
const db = createDatabase({ dialect: 'sqlite', connection: { filename: ':memory:' }, migrations: { auto: true } });
await db.connect();
await db.rawRun('CREATE TABLE "notes" ("id" text NOT NULL PRIMARY KEY, "title" text NOT NULL)');
console.log('自动补列:', JSON.stringify(await db.sync([Note])));     // → altered: ["notes"]
console.log('列:', (await db.inspectTable('notes')).columns.map((c) => c.name).join(','));

// 不安全的三件事一定被拒绝：删列、改类型、加"NOT NULL 且无默认值"的列
const Strict = defineModel({
  name: 'strict',
  fields: { id: { type: 'uuid', primaryKey: true }, must: { type: 'string', notNull: true } },
});
await db.rawRun('CREATE TABLE "strict" ("id" text NOT NULL PRIMARY KEY)');
await db.sync([Strict]).then(
  () => { throw new Error('不安全的自动迁移不该成功'); },
  (err) => console.log('不安全被拒:', err.name),
);
await db.close();
```

## 仓储：CRUD + 乐观锁 + 关联

```js verify
import { createDatabase, defineModel, DbConflictError } from '@actor/db';

const Note = defineModel({
  name: 'notes',
  fields: {
    id: { type: 'uuid', primaryKey: true },
    title: { type: 'string', notNull: true },
    tags: { type: 'json', default: [] },
    version: { type: 'integer', version: true },
  },
  relations: { comments: { kind: 'hasMany', model: 'comments', foreignKey: 'noteId' } },
});
const Comment = defineModel({
  name: 'comments',
  fields: {
    id: { type: 'uuid', primaryKey: true },
    noteId: { type: 'string', column: 'note_id', notNull: true },
    body: { type: 'text', notNull: true },
  },
});

const db = createDatabase({ dialect: 'sqlite', connection: { filename: ':memory:' } });
await db.connect();
await db.sync([Note, Comment]);           // sync 会注册 model，关联才能按名字解析

const notes = db.repository(Note);
const comments = db.repository(Comment);

const created = await notes.insert({ title: 'hello', tags: ['a', 'b'] });
console.log('插入 →', created.id, created.version, JSON.stringify(created.tags));

const updated = await notes.update(String(created.id), { title: 'hello v2' }, { expectedVersion: 0 });
console.log('更新 →', updated.title, 'version =', updated.version);

try {
  await notes.update(String(created.id), { title: 'stale' }, { expectedVersion: 0 });
  throw new Error('过期版本不该成功');
} catch (err) {
  if (!(err instanceof DbConflictError)) throw err;
  console.log('乐观锁 →', err.name);
}

await comments.insert({ noteId: String(created.id), body: 'first' });
const related = await notes.related(created, 'comments');
console.log('关联 →', (await related.many()).map((c) => c.body).join(','));

console.log('删除 →', await notes.delete(String(created.id)), await notes.findById(String(created.id)));
await db.close();
```

`findMany` 的条件键必须是 **model 的字段名**（框架会校验，值全部走参数占位符）：

```js verify
import { createDatabase, defineModel } from '@actor/db';

const Note = defineModel({
  name: 'notes',
  fields: { id: { type: 'uuid', primaryKey: true }, title: { type: 'string', notNull: true }, ownerId: { type: 'string', column: 'owner_id' } },
});
const db = createDatabase({ dialect: 'sqlite', connection: { filename: ':memory:' } });
await db.connect();
await db.sync([Note]);
const notes = db.repository(Note);
await notes.insert({ title: 'b', ownerId: 'u1' });
await notes.insert({ title: 'a', ownerId: 'u1' });
await notes.insert({ title: 'c', ownerId: 'u2' });

console.log('过滤+排序:', (await notes.findMany({ where: { ownerId: 'u1' }, orderBy: [{ field: 'title', direction: 'asc' }] })).map((n) => n.title).join(','));
await notes.findMany({ where: { 'title = 1 OR 1=1 --': 'x' } }).then(
  () => { throw new Error('未知字段名不该被当成 SQL 片段'); },
  (err) => console.log('未知条件被拒:', err.name),
);
await db.close();
```

## 自增整数主键

想要数据库生成 id（而不是框架生成 uuid），声明 `autoIncrement: true` —— 只能用在**整数类型**且**必须是主键**：

```js verify
import { createDatabase, defineModel } from '@actor/db';

const Note = defineModel({
  name: 'notes',
  fields: {
    id: { type: 'integer', primaryKey: true, autoIncrement: true },
    title: { type: 'string', notNull: true },
  },
});

// 三方言的身份策略不同，框架按方言生成（不假装统一）
console.log(Note.createTableSql('pgsql'));   // … "id" integer GENERATED BY DEFAULT AS IDENTITY NOT NULL PRIMARY KEY …
console.log(Note.createTableSql('mysql'));   // … `id` int NOT NULL AUTO_INCREMENT PRIMARY KEY …
console.log(Note.createTableSql('sqlite'));  // … "id" integer PRIMARY KEY AUTOINCREMENT …

const db = createDatabase({ dialect: 'sqlite', connection: { filename: ':memory:' } });
await db.connect();
await db.sync([Note]);
const notes = db.repository(Note);

// 不给 id：框架省略该列，写入后**回读**数据库生成的值（pg/sqlite 用 RETURNING，mysql 用 insertId）
const first = await notes.insert({ title: 'first' });
const second = await notes.insert({ title: 'second' });
console.log('生成的 id →', first.id, second.id);
if (typeof first.id !== 'number' || Number(second.id) !== Number(first.id) + 1) {
  throw new Error('自增没有生效或没有回读');
}

// 显式给 id 仍然允许（PG 用的是 BY DEFAULT，不是 ALWAYS）
const explicit = await notes.insert({ id: 100, title: 'explicit' });
console.log('显式 id →', explicit.id);
await db.close();
```

要点与取舍：

- **回读方式按方言**：PostgreSQL / SQLite 用 `INSERT … RETURNING`；MySQL 没有 RETURNING，只能用结果里的 `insertId`
  （驱动没实现回读能力时，框架会**明确报错**，而不是返回一个没有 id 的实体）。
- **PG 用 `GENERATED BY DEFAULT`（不是 `ALWAYS`）**：显式给 id 的插入（数据迁移、测试固定 id）仍然能跑。
- **`integer` 之外的整数类型也可以**：`tinyint`/`smallint`/`bigint` 都支持（SQLite 一律落到 `integer`）。
- 自增是**身份策略**而不是列类型，所以它与 `uuid` 主键互斥；同时**一个 model 只能有一个**主键，这条校验会直接报错。
- 如果你要"跨节点/跨库都不冲突的 id"，用默认的 `uuid` 主键更合适；自增 id 只在单库自增序列里唯一。

## 用户可写的两层映射

字段级（列 ↔ 领域值）与整行级（行 ↔ 实体）都能自己写。这是"把已有表接进领域模型"的关键：

```js verify
import { createDatabase, defineModel } from '@actor/db';

const Item = defineModel({
  name: 'items',
  fields: {
    id: { type: 'string', primaryKey: true },
    // 库里存的是逗号串，领域里是数组：两个钩子都由你写
    tags: {
      type: 'text',
      parse: (raw) => (raw ? String(raw).split(',') : []),
      serialize: (value) => (Array.isArray(value) ? value.join(',') : String(value)),
    },
    level: { type: 'integer', default: 1 },
  },
  // 整行级：把 level 映射成领域里的 grade（虚拟字段，不落库）
  parseRow: (row) => ({ ...row, grade: Number(row.level) >= 5 ? 'high' : 'low' }),
  serializeRow: (entity) => (entity.grade === 'high' ? { ...entity, level: 9 } : entity),
});

const db = createDatabase({ dialect: 'sqlite', connection: { filename: ':memory:' } });
await db.connect();
await db.sync([Item]);
const items = db.repository(Item);
await items.insert({ id: 'i1', tags: ['x', 'y'], grade: 'high' });

const found = await items.findById('i1');
console.log('映射回来 →', JSON.stringify(found.tags), found.grade);
console.log('落盘的 level →', (await db.raw('SELECT level FROM "items" WHERE id = ?', ['i1']))[0].level);
await db.close();
```

> 注意：提供了 `serializeRow` 时，领域实体**允许**带虚拟字段；没有提供时，多写一个不存在的字段名会**直接报错**
> （避免"看起来插入了"其实什么都没写）。

## 逃生通道：`raw()` 与 `@actor/data` 组合

```js verify
import { createDatabase, defineModel } from '@actor/db';
import { createSqlRepository } from '@actor/data';

const Note = defineModel({
  name: 'notes',
  // 注意：@actor/data 的仓储按约定需要 version 列（乐观锁），所以这里带上它
  fields: {
    id: { type: 'uuid', primaryKey: true },
    title: { type: 'string', notNull: true },
    version: { type: 'integer', version: true },
  },
});
const db = createDatabase({ dialect: 'sqlite', connection: { filename: ':memory:' } });
await db.connect();
await db.sync([Note]);

// 手写 SQL（仍然参数化）
await db.rawRun('INSERT INTO "notes" (id, title, version) VALUES (?, ?, ?)', ['n1', 'raw', 0]);
console.log('raw →', (await db.raw('SELECT title FROM "notes" WHERE id = ?', ['n1']))[0].title);

// db.runner() 与 @actor/data 的 SqlRunner **结构兼容**：需要游标分页/outbox/投影时直接用那边
const repo = createSqlRepository({ runner: db.runner(), table: 'notes', fields: ['id', 'version', 'title'] });
console.log('@actor/data 仓储 →', (await repo.findById('n1'))?.title);
await db.close();
```

**分工**：`@actor/db` 管连接、方言、model 与映射；`@actor/data` 管仓储语义（游标分页、outbox、
投影、迁移 runner、事件演进）。两边用上面的 `runner()` 组合，不需要二选一。

## 接进 `@actor/app` 与 Web 层（**开箱可用**）

推荐直接用 `databasePlugin`：它负责连接、健康检查、建表、把 `db` 与仓储**注册成应用服务**，
并在停机时优雅关池。业务代码（控制器）只需要 `ctx.get('notes')`：

```js
// src/app.ts —— 数据库只出现在这一行
import { databasePlugin } from '@actor/db';
import { Note } from './models.ts';

export default defineApp({
  config,
  modules: [notesModule],
  plugins: [
    databasePlugin({
      models: [Note],
      repositories: { notes: Note },   // 控制器里： ctx.get('notes')
      autoMigrate: true,               // 演示方便；生产建议关掉、走显式迁移
    }),
    httpPlugin({ port: 0 }),
  ],
});
```

```js
// src/controllers.ts —— 只依赖注入进来的仓储，不关心方言
import { defineController } from '@actor/web';
export const notesController = {
  create: defineController({
    input: { title: { type: 'string', min: 1 } },
    async handle(input, ctx) {
      const notes = ctx.get('notes');           // ← 插件注册的仓储
      return notes.insert({ title: input.title });
    },
  }),
};
```

**配置**：插件自带配置节 `plugins.db.*`，用环境变量覆盖（双下划线表示层级）：

| 配置项 | 默认 | 说明 |
|---|---|---|
| `plugins.db.driver` | `sqlite` | `sqlite` / `pgsql` / `mysql`（给 `url` 时按 DSN 推断，可省） |
| `plugins.db.url` | 空 | DSN，例如 `pgsql://user:pass@host:5432/db`（此时记得 `npm i pg`） |
| `plugins.db.file` | `./data/app.sqlite` | sqlite 的文件路径（`:memory:` 也行） |
| `plugins.db.poolMax` | `10` | 池上限（映射到各驱动的真实字段名） |
| `plugins.db.autoMigrate` | `false` | 是否允许 `sync()` 自动补**安全**的列 |

```bash
APP_PLUGINS__DB__URL='pgsql://user:pass@host:5432/appdb' node main.ts
```

插件注册的服务名：`db`（`Database` 句柄，可用 `raw()`/`healthCheck()`/`inspectTable()`）+
你在 `repositories` 里声明的每个名字（仓储）。**连不上就启动失败**，不会出现"应用起来了但数据库没连上"。

> 插件默认方言是 **sqlite**（零依赖、开箱可用）；包级 `createDatabase()` 的默认方言仍是 **pgsql**。
> 想手写接线也可以（不走插件）：注意 **provider 是同步解析的**（app 解析依赖时不会 await 你的 promise），
> 所以要在 provider 里同步建句柄并返回仓储（惰性 runner 让它先可用），把 `connect()`/`sync()` 放进 `onStart`、
> 把 `db.close()` 放进 `onStop` —— 这也正是 `databasePlugin` 内部做的事。

完整可跑示例：[`examples/app-db`](../../../examples/app-db/README.md)。

## 怎么跑真库测试（可选的"真验"）

上面的 PG/MySQL/SQL Server 目前是**契约级验证**（离线、不引驱动）。想真连库：

```bash
node scripts/dev-databases.mjs up               # docker 起 pg/mysql/mssql/redis/mongo
eval "$(node scripts/dev-databases.mjs env)"    # 导出 ACTOR_TEST_*_URL
npm test                                        # 真库用例这时才真的跑
node scripts/dev-databases.mjs down             # 收工（-v 一起清数据卷）
```

没设变量时那些用例会**显式跳过** —— `npm test` 的输出里能看到 `skipped N`，跳过原因写明是哪个变量没设，
**不会静默变绿**（静默绿灯会让人以为真库验过了）。

不想用 docker 就直接指向你自己的库：

```bash
ACTOR_TEST_PG_URL='pgsql://user:pass@your-host:5432/db' npm test
```

真库用例跑的是**同一套**连接管理契约断言（`@actor/db-core` 的 `runManagedConnectionContract`），
不是另写一套宽松断言 —— 这样"契约级"与"真库"说的是一回事。

## 诚实的边界（请先读这段）

- **SQLite 是"真库验证"**：本仓库的测试用 Node 内置 `node:sqlite` 跑真实 SQL（建表、漂移、乐观锁、关联、事务）。
- **PostgreSQL / MySQL / SQL Server 目前只到"契约级验证"**：本仓库**离线且不引驱动**，所以这三个方言验证的是
  **池参数映射、占位符与引号风格、DDL/内省 SQL 文本、事务是否用专用连接并归还**（SQL Server 还验证了
  `@pN` 绑定与 `SCOPE_IDENTITY` 回读）—— **真连库行为未经本仓库验证**。
  上生产前请在你的环境里跑一次 `db.connect()` + `db.sync([...])`。
- **自动迁移只做安全操作**：加可空列 / 有默认值的列 / 建索引。删列、改类型、加 `NOT NULL` 无默认值的列
  一律拒绝并要求你写迁移 —— 这是运维决策，不该由框架替你决定。
- **`sync()` 的类型比较是"规范化后的宽松比较"**：它抓明显不一致（例如 `text` vs `integer`），
  不做完整的类型系统（方言别名、精度差异可能不报）。
