| # | 审计发现 | 修复 |
|---|---|---|
| S1 | 🔴 网关默认零认证，且库内没有"非回环必须 TLS"的守卫（README 却推荐 `0.0.0.0`） | `Gateway.assertSafeBinding()`：非回环 + 无 TLS → **拒绝启动**（`allowInsecureBinding: true` 才能放行）；README:148 的示例改成配 TLS 并说明该守卫 |
| S7 | 🔴 TLS 的 `requestCert=false` + `verifyNodeId=false` = 零客户端认证 | 组合出现即拒绝启动；只关 `verifyNodeId`（滚动升级）时放行但**大声记一条** `tls_node_id_verification_disabled` |
| — | 🟠 `Gateway` 的 `emit('error')` 在无监听者时抛 → `listen()` 的 `reject` 永不执行 | 新增 `_safeEmit`/`_logSafe`：监听器抛错不影响内核；`listen()` 现在**一定会** resolve/reject |
| S4 | 🟠 网关入站无在途上限（一条连接就能堆无限 handler，drain 永远排不空） | `maxInflightPerConnection`（默认 1000），超限发 `overloaded` + 断开 |
| S2 | 🔴 gossip 注册表可被投毒/撑爆、可注入任意拨号地址 | `maxRegistryEntries`（默认 10000）、`maxPeers`（默认 256）、`ts` 超前本机超过 60s 即拒；被拒时发 `registry_rejected`/`peer_limit_reached`（**可见**） |
| S12 | 🟠 `exportState()` 把字符数当字节数 | 改用 `Buffer.byteLength(..., 'utf8')` |
| S3 | 🔴 WS 分片消息没有累计长度上限（`maxPayloadBytes` 对分片是假的） | 服务端**与客户端**都在累加前校验，超限 `_fail(1009)` |
| S9 | 🟠 控制帧不校验 ≤125 与 FIN（1 MiB PING 原样回成 1 MiB PONG） | 两端都加 RFC 6455 §5.5 校验（`_fail(1002)`） |
| S5 | 🟠 WS 无连接数上限；README 声称的"非回环拒绝启动"只在示例里 | `maxConnections`（默认 1000）+ 用"已进入 upgrade 的计数"封并发入口；`WebSocketServer.assertSafeBinding()` 让那句文档**成真** |
| F7 | 🟠 `system.peers` 可被入站帧被动撑大 | `maxPeers`（默认 128），超限**明确拒绝**并记 `peer_limit_reached` |
