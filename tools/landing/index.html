监督树与失败语义

父 Actor 就是子 Actor 的监督者。one_for_one / rest_for_one / one_for_all 三种策略 + 重启强度（次数/时间窗）。

  • 孩子超出重启强度 → 升级给祖父决定，不会静默放弃
  • failure: 'crash' | 'retry' 显式选择：崩溃是信号，或按指数退避重试后进死信
  • 顶层耗尽强度 → system_failure 事件 + 如实停机

单 FIFO 邮箱与背压

每个 Actor 一条队列、串行处理：读-改-写不会交错，用不着锁（20 条并发消息，一条都不丢 —— 文档里有断言）。

  • 满邮箱语义显式：reject / drop-oldest / drop-newest
  • 拒绝/丢弃都留痕：mailbox_full 事件 + 计数器
  • 消息进死信队列：内存环 + 可选落盘（重启后还在）

持久化：快照或事件

mode: 'snapshot' 或 mode: 'events'，状态只放 this.state 就自动恢复；后端可插拔（内存 / 文件 / LevelDB / 自定义）。

  • 重启后状态还在（示例真跑：重启前 41 → 重启后 41）
  • 写入失败不静默：PersistenceError / 乐观锁冲突 PersistenceConflictError
  • 没配存储却要持久化 → 启动期就报错，不会等到第一个请求

零运行时依赖 · 无构建步骤

主仓库的 devDependencies 只有 typescript 与 @types/node；内核只用 Node 内置模块。

  • Node ≥ 24：靠原生类型剥离直接跑 .ts，没有编译产物
  • 唯一可选依赖是 LevelDB 后端（classic-level），缺失自动跳过
  • 数据库/缓存/邮件适配器不把驱动写进依赖：由调用方注入

分层装配与配置

内核只管 Actor；@actor/app 负责配置校验、依赖注入、模块与插件装配，@actor/web 只管路由与控制器。

  • 配置在启动期校验（unknown key / 类型错误 / 缺必填都当场报）
  • 依赖缺了就启动失败，而不是运行期拿到 undefined
  • 保留名有单一来源，撞了就报错，不靠约定

可观测性：一个出口

日志一处配好（logging），三类事件汇到一个出口；错误有显式出口（errors），后台失败不再不可见。

  • 请求级子日志自动带 requestId，meta 默认脱敏（token/cookie/password…）
  • 指标、全链路 Trace、OTLP 导出按需启用
  • 慢请求必记（不受采样影响）；诊断路由默认关闭、需 token

集群：Gossip + TCP 网关

对等节点用 Gossip 维护名册，用 TCP 网关（Protobuf 帧、可选双向 TLS）互相通信，跨节点 ask/tell 同一套 API。

  • 寻址是路径；本节点没有就查名册，再走网关
  • 心跳判活、失败计数、节点退出会被观察到
  • 共享存储才能跨节点交接有状态 Actor（文档明确写了边界）

数据层与中间件

@actor/data 给事件溯源、快照、仓储、Outbox、投影；@actor/db 用 defineModel 声明表并在三种方言上渲染。

  • 游标分页（并发写入下不漏不重），乐观锁冲突映射成 409
  • Redis / MongoDB / 邮件适配器都走受管资源：健康检查、保活、drain、关闭
  • 迁移有版本表、幂等、可回滚，中断可重入

工具链：CLI 与 testkit

actor 一条命令起项目、生成骨架、迁移、体检；@actor/testkit 提供虚拟时钟与故障注入。

  • generate 九种骨架，非破坏：不覆盖你的文件，只打印待粘贴的接线片段
  • 自定义命令：.actor/commands/*.ts 写好就是 actor 的子命令（子进程隔离执行）
  • 虚拟时钟把"等一小时"变成 0 真实毫秒

为什么可以信

不吹牛的部分：每条主张都有门禁守着

框架代码没有构建步骤，所以"纪律"必须靠可执行的检查来维持 —— 这些检查就在仓库的 npm test 里。

文档里的示例在 CI 真执行每篇指南至少一个 ```verify 块，逐块跑；跑不通就红。
语法糖与显式写法可证等价sugar 写法必须与啰嗦写法 deepStrictEqual，否则视为 bug。
库代码不许裸 console每个输出点要带理由标记，并有"证伪用例"保证门禁真的会响。
启动期失败优于运行期事故配置错、依赖缺、必须的能力没装 —— 都在 start() 当场报错并指出修法。
生成器不破坏你的代码已存在的文件默认拒绝覆盖，--dry-run 一个字节都不写。
退出码有意义CLI：0 成功 / 1 用法错 / 2 环境问题；脚本与 CI 能区分。
文档站零断链相对链接指向不存在的文件 → 构建直接失败并列出清单。
不留"以后再说"的暗账类型没补齐的文件带显式 @ts-nocheck 标记，并在 API 参考里如实标注。
装配方式

12 个包，按需启用

内核不知道 HTTP、数据库、集群治理；每加一项能力，你就多装一个包 —— 边界清晰，加载面可控。

包负责什么运行时依赖
nodejs-actor-framework内核：Actor、监督树、邮箱与背压、持久化、事件、指标与 Trace、集群与网关零 可选 LevelDB
@actor/app应用层：配置校验、依赖注入、模块与插件装配、错误与日志出口内核
@actor/webWeb 层：路由、控制器、中间件、上传、鉴权、访问日志、诊断路由app
@actor/data数据层：事件溯源、快照、仓储、Outbox、投影、迁移零

上手

三条命令，一个能跑的服务

要求 Node.js ≥ 24。脚手架不自动装依赖、不覆盖已有文件；生成完会告诉你下一步做什么。

建项目

选布局与能力（Web / 数据 / 上传 / 鉴权 / 调试 / Redis / 邮件）。

生成骨架

控制器、Actor、服务、模型、表结构、中间件、测试 —— 九种，都自带能跑的测试。

体检再启动

doctor 检查 Node 版本、依赖、配置、数据目录、迁移、端口占用与命令定义。

terminal
# 1) 建一个带 Web 与数据层的项目（layered 布局）
npx @actor/cli new app my-service --with web,data

# 2) 生成一个控制器 + 一个 Actor + 它的表（--dry-run 可以先看计划）
cd my-service
npx @actor/cli generate controller notes
npx @actor/cli generate actor cart
npx @actor/cli generate schema notes --field title:string --field done:bool --optimistic-lock

# 3) 体检 → 起服务（脚手架不自动装依赖，按提示装你自己的）
npx @actor/cli doctor
npm start
